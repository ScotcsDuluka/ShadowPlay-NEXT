## Follow-up same day: motion factory default + repaint artifact (owner request)

The owner reported a rapidly color-alternating square at the overlay's top-left corner
during overlay start that then disappears. Root cause: the Motion engine's forced-repaint
canvas (`osc-motion.js` `touchPaint()`) — a 1×1 canvas at `position:fixed;left:0;top:0`
(opacity .01, max z-index) filled alternating `#fff`/`#000` once per frame while a motion
phase is active, removed at idle (`stopPaint()`). It is designed to be imperceptible; a
visible square means the OSR/shared-texture render path draws that compositing layer
larger than 1px (GPU-path owner to confirm; host files under concurrent work).

Changes applied (Project mods → Module → Build, hashes refreshed, parity verified):
1. `osc-motion-timing.js` factory default `enabled:false` — the owner had already set
   motion off in the running overlay (localStorage `DulukaOscMotionSettings`, persisted
   2026-10-29 00:41) and asked for these values to become the defaults. All other motion
   values equal the previous defaults; Background settings had no stored overrides, so
   their defaults are unchanged.
2. `osc-motion.js` `touchPaint()` now alternates `#010101`/`#000` — the repaint kick only
   needs the canvas content to change, and the imperceptible delta removes the visible
   flash even if the render path keeps enlarging the layer.

Tests: `oscMotion.test.js` 45/45 (fixture seeds motion ON explicitly), `oscMotionSettings.test.js`
5/5, `oscBackground.test.js` 27/28 (remaining failure pre-existing at baseline), profile
suite 14/14; full NodeAPI suite shows no new failures versus the pre-session baseline.
