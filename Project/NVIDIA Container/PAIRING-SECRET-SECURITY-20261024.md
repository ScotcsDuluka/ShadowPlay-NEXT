## Implemented hardening

1. PairingSecretStore.cs: Windows DPAPI CryptProtectData/CryptUnprotectData, CurrentUser scope, noninteractive; fixed 32-hex credential format for legacy compatibility. Persistent file under per-user LocalAppData/ShadowPlay NEXT/Secrets/pairing-current-user.dpapi.
2. Explicit one-time CSPRNG (128-bit) generation supported by pairing manager, but never automatically performed at Container startup. Startup reads protected store first. Existing runtime can still read legacy config until cutover; corrupt/unreadable protected store never silently falls back to an old config.
3. PairingSecretManager CLI: audit/migrate/generate. Real system was enrolled using migrate with the **same existing runtime value**, NOT rotated. Manager never echoes plaintext or returns it through API.
4. Tracked Project/NVIDIA Config/nvcontainer.json no longer contains pairing.secret. Tracked example Project/NVIDIA Config/nvnode/nvnode-init-duluka.json was sanitized.
5. Removed compiled-source hardcoded credential fallback from NvContainer, OSC active/archived sources, Capture ShadowPlayRest, and legacy DulukaPort source. Old compiled binaries and Git history retain risk until release/rotation.
6. Build Scripts/build-dev.ps1 preserves existing runtime nvcontainer.json and excludes the tracked NvNode init example from copy. Brand-new deployments require pre-enrolled DPAPI store; no hidden rotation from build scripts.
7. Git guard Scripts/Test-PairingSecrets.ps1 with .githooks/pre-commit, enabled via local core.hooksPath=.githooks. Blocks staged DPAPI/private files, nonempty pairing.secret in nvcontainer JSON, and embedded 32hex-like secret literals. Working-tree scan passed across 3,112 tracked files.

## Remaining risks (NOT FULLY SECURE YET)

- **Historical exposure:** old secret appears in earlier commits; Git history was NOT rewritten. Old secret remains usable. Any prior sharing of the repository exposes it. After migration, coordinated rotation/revocation is necessary.
- **Runtime legacy plaintext:** active Build nvcontainer.json and per-user NvNode init remain plaintext for compatibility. Current MMF exposes plaintext to processes allowed by its DACL. DPAPI does not encrypt MMF/HTTP.
- **No end-to-end mutual authentication:** local loopback API guards (Host/Origin/fetch metadata) mitigate browser abuse, not malicious same-user local processes. NodeAPI's securityCookie is independent and OSC's disableSecurity path requires separate review.
- **IPC replay/identity:** named mapping/event does not implement nonce/challenge, anti-replay, or per-process authorization. Hook and Capture transports require owner-specific review; no false claim of an authenticated central IPC bus.
- The actual OS profile identity must stay consistent for CurrentUser DPAPI decrypt. A different Windows account/service account requires separate provisioning and authorized migration.
- Historical binaries and other external copies may contain a key in executable memory or embedded literals; source cleanup does not strip already-deployed binaries.
