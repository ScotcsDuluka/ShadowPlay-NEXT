# Phase 6D — Synthetic FFmpeg session stop/failure/recovery

Date: 2026-10-24. Branch: `Stable`. Owner scope: `Project/NVIDIA Capture` only.

## Safety boundary

This phase **did not** start NvCapture's installed executable, capture the desktop, access WASAPI speakers or microphone, inject into a game, use NVENC/D3D11, or restart the running worker. The user's music was never sampled or saved. All video was generated by **FFmpeg `lavfi:testsrc2` internally**. Synthetic test inputs explicitly use `-f lavfi`, `-an` (no audio), `libx264`, and `-re` (real-time pacing). The controlled FFmpeg processes use below-normal host priority and a unique output directory under the test assembly's `bin/Release` path; test-created output and any test-owned child are cleaned up in `Finally`/`Dispose`.

## Scope implemented

- New independent `EngineCapture/SessionRecovery.Tests` .NET 10 VB executable.
- Links the **production `src/[API]/CaptureMediaInspector.vb`** into the test; checks actual finalized MP4 with the real read-only bounded ffprobe inspector, not a mock inspector.
- Five actual **synthetic FFmpeg process sessions per run**:
  1. Clean early stop of testsrc2/libx264 encoding via FFmpeg stdin `q`; stop is signaled twice, exit code must equal zero, child must exit, and MP4 must have exactly one video stream, zero audio streams, a bounded nonzero duration, and a real payload.
  2. Invalid encoder name `shadowplay_invalid_encoder` must exit nonzero, leave no child, and not produce a verified MP4.
  3. Intentional kill of **only** the test-owned FFmpeg child. Session exit must be nonzero and must never be accepted as success, even if a fragment or temporary file looks structurally parsable.
  4. Fresh FFmpeg session after both failure types. It must finalize and produce a verified video-only MP4.
  5. Second clean stop as an additional recovery/stop repeat.
- The test never invokes `Invoke-CaptureSmoke.ps1 -RunSmoke`, because that script uses `gdigrab` or real desktop duplication and would record the user's actual screen.
- `NVIDIA Capture.vbproj` excludes `SessionRecovery.Tests/**/*.vb` from the SDK WinForms recursive compile glob.


## Remaining Phase 6D / Phase 7 gates

- This tests real FFmpeg child lifecycle, the MP4 file, and **CaptureMediaInspector**; it does **not** call the live NvCapture REST `/record/start` or prove the production UI/engine state machine survives a real NVENC fault. The separate Phase 6C tested RecordingEngine's failure-state reporting without initializing GPU devices.
- Failure detection here requires **both** a clean process exit and valid MP4 evidence. The inspector intentionally validates structural media only, not FFmpeg exit status.
- Real Windows system audio, microphone selection, long-term A/V sync, actual GPU driver recovery, and gameplay frame pacing are unverified.
- For real audio validation, first obtain the user's informed permission to record a controlled audio sample; their currently playing music is **not** test material by default.
- Notify the user before changing OSC UI/OSC transport/NvContainer.
